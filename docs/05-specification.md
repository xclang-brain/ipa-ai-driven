## 2. 移行後の文書のフォルダ

1つの文書を、1つのフォルダに移行する。

```
migrated/<文書ID>/
  document.md         移行後の文書（正本になるもの）
  extract.json        原本から取り出した中間データ（検査で使う。編集しない）
  figures/            原本の図の画像（編集しない）
  media/              原本に貼り付けられていた画像
  verify-report.json  最後に行った検査の結果
  review-notes.md     確認するエージェントが書く確認の記録
```

## 3. 移行後の文書（document.md）の書式

### 3.1 属性

文書の先頭に、`---` で囲んで属性を書く。

| 属性 | 内容 | 対応する要件 |
|---|---|---|
| `doc_id` | 文書ID | |
| `title` | 文書名（原本のファイル名から拡張子を除いたもの） | |
| `source_file` | 原本のファイルの場所 | FR-010 |
| `source_sha256` | 原本のハッシュ値 | FR-010 |
| `review_status` | 確認の状態。`未確認`、`AI確認済み`、`承認済み` のいずれか | FR-009 |
| `migrated_with` | 下書きを作った道具と版 | |

作成日時は属性に入れない。同じ原本から常に同じ下書きが得られるようにするためである（NFR-003）。履歴は Git で追う。

### 3.2 本文

- 文書名を `#` の見出し、シート名を `##` の見出しにする。この2種類の見出しは道具が付けたものであり、検査では本文として数えない。
- シートの中は、空行で区切られたセルのまとまり（ブロック）ごとに出力する。2行以上で、複数のセルを持つ行があるブロックは表にする。それ以外は文章にする。
- 表の1行目を見出しにするのは、1行目のセルがすべて塗りつぶされていて、2行目以降がそうでない場合に限る。それ以外は、見出しを空にする。見出しでない行を見出しとして扱うと、内容の意味が変わるためである。
- 複数のシートの先頭で同じ内容が繰り返されるブロック（PJ名、成果物名などの見出し欄）は、`## 文書の属性` に1回だけ出力する（[要求分析](04-analysis.md) 1章）。
- 日付は `YYYY-MM-DD` で書く。原本の表示形式（和暦、月日だけの表示など）は再現しない。

### 3.3 由来の記録

各ブロックの直前に、原本の場所をコメントで書く（FR-008）。

```
<!-- src: sheet="変更履歴" range="A7:AI8" -->
```

### 3.4 図の枠

図形や線のあるシートには、図の枠を1つ置く。

```
<!-- figure:begin id="fig-s4" sheet="1. 企業情報管理(11AA)" -->
![原本の図](figures/sheet-04-p1.png)

<!-- transcription:todo -->
<!-- figure:end -->
```

- 下書きでは、枠の中に `<!-- transcription:todo -->` を置く。これが残っている図は未記入として扱う（FR-012）。
- 書き起こしでは、この印を Mermaid の図と文章に置き換える。
- Mermaid の節点の名前は `s` + 原本の図形ID とする。図の中の節点から、原本の図形を追えるようにするためである（FR-008）。
- そのシートの図形の文字は、すべて枠の中に書く（FR-012）。

初回は、1つのシートにある図形を1つの図として扱う。1つのシートに複数の図が離れて描かれている場合の分け方は、2回目以降で決める。

### 3.5 要確認の印

読み取れなかった箇所、確信の持てない箇所には、次の形式の印を付ける（FR-013）。

```
【要確認: 理由】
```

印は検査で数えて一覧にする。印が残っている文書は `承認済み` にできない。道具も、取り出せないもの（貼り付け画像の内容、グラフなど）にこの印を付ける。

## 4. 検査の合否

`docmig verify` は、次のいずれかがあると不合格にする。

| 誤り | 内容 | 要件 |
|---|---|---|
| 原本の不一致 | 属性のハッシュ値が中間データと違う。原本のファイルの内容が中間データと違う | FR-010 |
| 文字の欠落 | 原本の文字列（セル、図形）が、本文にない。出現回数が足りない | FR-011 |
| 図の枠がない、図が未記入 | 図形のあるシートに図の枠がない。未記入の印が残っている | FR-012 |
| 図の文字の欠落 | 図形の文字が、その図の枠の中にない | FR-012 |
| 状態が不正 | `review_status` が3つの値のいずれでもない | FR-009 |
| 状態の矛盾 | 上の誤りがあるのに `AI確認済み` や `承認済み` になっている。要確認の印が残っているのに `承認済み` になっている | FR-009、FR-013 |

文字の照合では、空白と改行の違いを無視する。長い文字列から順に探し、見つけた部分は使用済みにする。「確認」のような短い文字列が、「企業情報登録確認」の一部として数えられることを防ぐためである。

### 検査で確かめられないこと

検査が確かめるのは、原本の文字が移行後の文書にあることである。次のことは確かめられない。確認するエージェントと人が確かめる。

- 矢印のつながりと向きが正しいか
- 矢印のラベルが正しい矢印に付いているか
- 原本にない内容が足されていないか
- Mermaid の記法が正しいか

また、1〜2文字の短い文字列（「1」「-」など）は、表の区切りや図の記法の中の同じ文字と区別できない。そのような文字列が欠けていても、検査で見つからないことがある。

## 5. 初回の範囲に含めないもの

| 対象 | 扱い |
|---|---|
| Word の文書 | 2回目以降。旧形式の図形（VML）への対応が要る（[要求分析](04-analysis.md) 3.2） |
| 貼り付け画像の内容の読み取り | 2回目以降。画像はファイルとして保存し、要確認の印を付ける。OCR の採否もそのときに決める |
| グラフ、SmartArt | 取り出しの対象外。要確認の印を付ける |
| 数値の表示形式（小数の桁数、通貨、パーセントなど） | 再現しない。保存されている値を出力する。原本の表示と違って見える場合がある |
| グループ全体にかかる回転と反転 | 反映しない。矢印の接続先の候補がずれる場合がある |
| セルの罫線、色、コメント | 取り出さない |
