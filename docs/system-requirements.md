# 要件一覧

このファイルは `tools/render_ledger.py` が台帳から出力したものである。内容を変えるときは台帳を編集し、出力し直す。

台帳: `requirements/system-requirements.yaml`　版 1.1（2026-11-22 更新）

対象: 移行ツール docmig と、Copilot CLI 用の定義一式

## FR-001 セルの取り出し

Excel ファイルの各シートから、値のあるセルの内容を、シート名とセル番地を付けて取り出すこと。

- 由来: REQ-001、REQ-002、REQ-013
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - サンプル文書の「変更履歴」シートのセルが、シート名とセル番地つきで中間データに含まれる
  - 数式のセルは、保存されている計算結果を取り出す
  - 日付のセルは YYYY-MM-DD の形式で取り出す。日本語環境の Excel に固有の日付の表示形式（和暦など）のセルも、日付として取り出す

## FR-002 結合セルの記録

結合セルは、左上のセルの値と結合範囲を記録すること。

- 由来: REQ-002
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - 結合セルの値が1回だけ取り出され、結合範囲が中間データに含まれる

## FR-003 図形の取り出し

各シートの図形について、図形ID、種類、文字、位置と大きさを取り出すこと。グループ化された図形は、グループの中の図形まで取り出し、位置をシート上の座標に直すこと。

- 由来: REQ-003、REQ-013
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - サンプル文書の「1. 企業情報管理(11AA)」シートから、文字を持つ図形46個の文字がすべて取り出される
  - 取り出した文字に「【W11AA0201】」を含む図形がある
  - グループの中の図形の位置が、グループの外枠の内側に収まる

## FR-004 矢印の取り出し

線とコネクタについて、始点と終点の座標、矢じりの有無、ファイルに記録された接続先を取り出すこと。回転と反転を反映すること。各端点について、最も近い図形を候補として記録すること。

- 由来: REQ-003
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - サンプル文書の「1. 企業情報管理(11AA)」シートから、コネクタ19本と、線として描かれた矢印1本が取り出される
  - ファイルに接続先が記録されている端点では、候補がその接続先と一致する
  - 180度回転したコネクタの始点と終点が、回転していない場合と入れ替わる
  - 端点が図形の辺の上にあるとき、その図形が候補として記録される
  - 近くに図形がない端点には、候補を記録しない

## FR-005 貼り付け画像の保存

シートに貼り付けられた画像を、ファイルとして保存し、位置を記録すること。画像の内容の読み取りは初回の範囲に含めない。

- 由来: REQ-004
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - 貼り付け画像を含むファイルから、画像がファイルとして保存され、中間データに位置と保存先が記録される

## FR-006 シートの描画

図形を含むシートを画像にし、どの画像がどのシートのものかを記録すること。依頼者の環境では Excel を、Excel がない環境では LibreOffice を使うこと。

- 由来: REQ-003、REQ-019
- 確かめ方: 自動テスト（LibreOffice）、依頼者環境（Excel）
- 状態: 実装済み
- 受入条件:
  - サンプル文書の図形を含むシートごとに、1枚以上の画像が作られる
  - 「1. 企業情報管理(11AA)」シートの画像が、そのシートのものとして記録される
  - Excel を使った描画が、依頼者の環境で動く

## FR-007 下書きの生成

中間データから Markdown の下書きを生成すること。文書の属性、シートごとの節、表、図の枠を含めること。複数のシートで同じ内容が繰り返される見出し欄は、1か所にまとめること。

- 由来: REQ-001、REQ-002、REQ-005
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - サンプル文書の下書きに、シートごとの節がシートの順に並ぶ
  - 「変更履歴」シートの内容が Markdown の表になる
  - 複数のシートで繰り返される見出し欄（PJ名など）が、下書きに1回だけ現れる
  - 図形を含むシートの節に、図の枠と、書き起こしが未記入であることを示す印がある

## FR-008 由来の記録

下書きの各ブロック（文章、表、図）に、原本のシート名とセル範囲を記録すること。図の書き起こしでは、図形IDが分かる形で節点を書くこと。

- 由来: REQ-013
- 確かめ方: 自動テスト、レビュー
- 状態: 検証済み
- 受入条件:
  - 下書きの各ブロックの直前に、シート名とセル範囲を書いたコメントがある
  - 図の書き起こしの手順に、節点の名前に図形IDを使う決まりが書かれている

## FR-009 確認の状態

移行後の文書の属性に、確認の状態（未確認、AI確認済み、承認済み）を持たせること。下書きの状態は「未確認」とすること。検査に不合格の文書が「AI確認済み」または「承認済み」になっている場合、検査で誤りとして報告すること。

- 由来: REQ-020、REQ-017
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - 下書きの状態が「未確認」である
  - 文字の欠落がある文書の状態を「AI確認済み」にすると、検査が不合格になる
  - 状態に3つ以外の値を書くと、検査が不合格になる

## FR-010 原本の識別

移行後の文書の属性に、原本のファイル名とハッシュ値（SHA-256）を記録すること。検査では、中間データのハッシュ値と一致すること、原本のファイルがあればその内容とも一致することを確かめること。

- 由来: REQ-015、REQ-012
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - 下書きの属性に、原本のファイル名とハッシュ値がある
  - 属性のハッシュ値を書き換えると、検査が不合格になる

## FR-011 文字の照合

原本から取り出した文字列（セルと図形）が、出現回数も含めて、移行後の文書の本文にすべて含まれることを調べ、欠落を一覧にすること。属性、コメント、道具が付けた見出し（文書名とシート名）の中の文字は、本文として数えないこと。

- 由来: REQ-012
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - 図の書き起こしが済んでいない下書きを検査すると、図形の文字が欠落として報告される
  - 本文から文字列を1つ削ると、その文字列とシート名、セル番地または図形IDが欠落として報告される
  - 同じ文字列が原本に3回あり、文書に2回しかない場合、1回分の欠落が報告される
  - 短い文字列が、それを含む長い文字列の一部として数えられない
  - シート名の見出しが、同じ文字のセルの代わりに数えられない

## FR-012 図の検査

図の枠ごとに、書き起こしが記入されていること、その図に属する図形の文字がすべて枠の中にあることを調べること。

- 由来: REQ-003、REQ-012
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - 未記入の印が残っている図の枠が、未記入として報告される
  - 図形の文字が別の図の枠にしかない場合、欠落として報告される

## FR-013 要確認の印

「【要確認: 理由】」の形式の印を数え、場所と理由を一覧にすること。印が残っている文書が「承認済み」になっている場合、検査で誤りとして報告すること。

- 由来: REQ-021
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - 文書の中の印の数と理由が、検査の結果に含まれる
  - 印が残っている文書の状態を「承認済み」にすると、検査が不合格になる

## FR-014 図を書き起こすエージェント

Copilot CLI 用のエージェント定義と、1つの図の図形・矢印を一覧にするコマンドを用意すること。エージェントは、図の画像と、その一覧をもとに、図の枠に Mermaid で図を書くこと。原本の文字列を変えないこと。読み取れない箇所や確信のない箇所には「【要確認: 理由】」の印を付けること。図の枠の外は変更しないこと。

- 由来: REQ-003、REQ-006、REQ-014、REQ-021
- 確かめ方: 自動テスト（一覧）、レビュー、依頼者環境
- 状態: 実装済み
- 受入条件:
  - エージェント定義に、上の4つの決まりが書かれている
  - 一覧に、節点の名前（s + 図形ID）、原本の文字、矢印の端点ごとの接続先の候補が載る
  - 依頼者の環境で、サンプル文書の図を書き起こし、検査（FR-011、FR-012）に合格する

## FR-015 確認するエージェント

Copilot CLI 用のエージェント定義を用意すること。エージェントは、書き起こしとは別の実行で、図の画像と書き起こした図を見比べ、食い違いを報告すること。検査に合格し、食い違いがない場合に限り、状態を「AI確認済み」に変えること。状態を「承認済み」に変えないこと。

- 由来: REQ-017、REQ-012
- 確かめ方: レビュー、依頼者環境
- 状態: 実装済み
- 受入条件:
  - エージェント定義に、状態を変える条件と、「承認済み」に変えない決まりが書かれている
  - 依頼者の環境で、わざと誤りを入れた図について、食い違いを報告する

## FR-016 移行後の文書の使い方の案内

Copilot CLI が読む指示ファイルに、移行後の文書の場所、確認の状態の意味、回答するときに由来（文書名と原本の箇所）を示すことを書くこと。

- 由来: REQ-008、REQ-013
- 確かめ方: レビュー、依頼者環境
- 状態: 実装済み
- 受入条件:
  - 指示ファイルに、上の3点が書かれている
  - 依頼者の環境で、移行後の文書に関する質問20問に答えさせ、正答数を記録する（成功の基準 S-3）

## NFR-001 外部と通信しない

移行ツールは、ネットワークを通じた通信を行わないこと。

- 由来: REQ-006
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - ツールのソースコードに、通信を行うライブラリの利用がない

## NFR-002 動作環境

移行ツールは、Windows の Python 3.10 以降で動くこと。Office は描画にだけ使うこと。

- 由来: REQ-019
- 確かめ方: 自動テスト（Linux）、依頼者環境（Windows）
- 状態: 実装済み
- 受入条件:
  - 取り出し、下書きの生成、検査が、Office のない環境で動く
  - 依頼者の環境（Windows）で、サンプル文書の移行が最後まで動く

## NFR-003 結果の再現性

同じ原本から、常に同じ中間データと下書きが得られること。

- 由来: REQ-012
- 確かめ方: 自動テスト
- 状態: 検証済み
- 受入条件:
  - 同じ原本を2回処理し、中間データと下書きが、作成日時を除いて一致する
